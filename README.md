# Swing Zone — дашборд разметки H4 и сигналы для торгового бота

Движок структуры **KHUSA SM PRO**. Автор логики и разметки — Vitaliy Yugay,
[vamp.09.94@gmail.com](mailto:vamp.09.94@gmail.com),
[github.com/YugayV](https://github.com/YugayV).

Инструмент по умолчанию — **XAUUSD**. Определяет **свинг-хай** и **свинг-лоу** на 4-часовом таймфрейме,
строит **площадь работы** (зона, equilibrium, premium/discount, OTE, сетка фибо),
рассчитывает торговый план и передаёт его боту в едином JSON-формате
`swing-zone/v1`. Финальное решение по входу принимает **ИИ-агент** на стороне бота.

```
┌───────────────┐   ┌──────────────┐   ┌──────────┐
│  Дашборд      │   │ TradingView  │   │   MT5    │
│  (браузер)    │   │ (Pine alert) │   │  (EA)    │
└───────┬───────┘   └──────┬───────┘   └────┬─────┘
        │  POST swing-zone/v1 (JSON)        │
        └───────────────┬───────────────────┘
                        ▼
              ┌─────────────────────┐
              │  Бот  /signal       │
              │  1. жёсткие правила │  ← R:R, риск, свежесть данных, символ
              │  2. ИИ-агент Claude │  ← enter / wait / skip + аргументы
              │  3. исполнение      │  ← по умолчанию dry-run
              └─────────────────────┘
```

Отдельно от торгового контура дашборд умеет спросить агента **«разбери ситуацию»**
(`POST /analyze`) — с разметкой и скриншотом графика. Ответ — чтение структуры и
рекомендации для человека, ордера при этом не выставляются.

в браузере.

## 1. Дашборд

Открывается на `/dashboard/` того же сервиса (или локально из `web/index.html`).
Все расчёты идут в браузере, котировки никуда не уходят, настройки хранятся в
`localStorage`.

### Ввод данных

Разбор живёт в `web/csv.js` — **этот же модуль использует бэктестер**, так что
дашборд и бэктест читают один файл абсолютно одинаково.

Колонки определяются **по заголовку**, а не по порядку. Это не придирка: у
investing.com порядок колонок

```
Date, Price, Open, High, Low, Vol., Change %
```

то есть закрытие идёт **вторым, до открытия**. Позиционный парсер прочитал бы
close как open, open как high, high как low — и построил структуру по
несуществующему графику, не выдав ни одной ошибки. Поэтому дашборд всегда
пишет в статусе распознанный порядок: `(по заголовку, порядок COHL)`.
Сверьте его один раз при первой загрузке нового источника.

Распознаются форматы:

| Источник | Как выгрузить | Пример строки |
|---|---|---|
| **MetaTrader 5** | Вид → Архив котировок → символ → Экспорт | `2026.07.28  04:00  3400.10  3425.80  3396.00  3412.50  1420` |
| **TradingView** | на графике ⋮ → Export chart data | `2026-07-28T04:00:00Z,3400.10,3425.80,3396.00,3412.50` |
| **investing.com** | Historical Data → Download Data (нужен бесплатный аккаунт) | `"07/28/2026","3,412.50","3,400.10","3,425.80","3,396.00","150.25K","0.37%"` |
| Dukascopy, Stooq и прочие | обычный CSV с шапкой | `Gmt time,Open,High,Low,Close,Volume` |
| Без шапки | любой экспорт | `2026-07-28 04:00,3400.10,3425.80,3396.00,3412.50` |

Разделители: `,` `;` таб, пробелы. Разбираются кавычки (`"3,412.50"` — одно
поле, а не два), разделители тысяч в обеих раскладках (`3,412.50` и
`3.412,50`), текстовые месяцы (`Aug 13, 2026`), unix-время, дата и время
разными колонками. Порядок строк не важен: investing.com отдаёт свежие
сверху — файл сортируется сам.

**Про даты вида `05/08/2026`.** Порядок день/месяц определяется по всему
столбцу: если хоть где-то первое число больше 12 — это ДД/ММ. Когда за весь
файл ни одно значение не превысило 12, различить нельзя; принимается
месяц/день (как у investing.com) и в статусе появляется предупреждение.
Надёжнее выгрузить файл с ISO-датами.

Таймфрейм определяется по фактическому шагу свечей и показывается в шапке —
если загрузили H1, а ждали H4, это видно сразу. Для склейки младших свечей в
H4 есть галочка **«Автоматически агрегировать в H4»**. Кнопка
**«Демо-данные»** даёт детерминированный набор из 140 свечей для проверки.

### Какие данные брать

Движок разметки завязан на точные хай и лоу: коррекция якорей ищет
экстремум между ними, а FIB 1 ловит касание уровня тенью. Разные источники
дают разные тени — у каждого свой набор поставщиков ликвидности, своё время
закрытия свечи и своя граница торгового дня.

Отсюда практическое правило: **размечать и тестировать нужно на том же
потоке, на котором торгуете.**

| Источник | Годится для | Оговорки |
|---|---|---|
| MT5 вашего брокера | разметка, бэктест, торговля | эталон: ровно те свечи, по которым исполнится ордер |
| TradingView (тот же провайдер, что на графике) | разметка | совпадает с тем, что вы видите глазами при ручной разметке |
| investing.com | прикидка, длинная история | сводный фид, не привязанный к брокеру: тени и границы дня будут отличаться от ваших |

investing.com удобен тем, что даёт длинную бесплатную историю без терминала.
Но давать по нему окончательную оценку стратегии не стоит: расхождение в
тенях сдвигает срабатывание FIB 1, а от него зависит вся дальнейшая цепочка
состояний. Прогоните бэктест на обоих источниках — если результаты сильно
разошлись, значит стратегия слишком чувствительна к фиду, и это само по себе
важный вывод.

Автоматической загрузки с investing.com в проекте нет намеренно: публичного
API у них не существует, а выкачивание страниц запрещено их же
пользовательским соглашением. Файл выгружается кнопкой Download Data и
переносится в дашборд.

### Скриншот вместо котировок

Вкладка **«Скриншот графика»** принимает картинку (перетаскиванием, `Ctrl+V` или
файлом). Кнопка **«Прочитать график»** превращает её в настоящие котировки —
дальше работает тот же движок структуры, что и для CSV.

Работа поделена так, чтобы каждый делал то, что умеет:

| Кто | Что делает | Почему так |
|---|---|---|
| Модель (`POST /vision`) | читает подписи ценовой шкалы, тикер, таймфрейм, границу поля свечей | это OCR, и здесь модель сильна |
| Браузер (`web/vision.js`) | находит свечи по пикселям: тени, тела, направление | модель плохо оценивает точные координаты, а цена нужна с точностью до пикселя |

Детектор классифицирует пиксели по насыщенности цвета, группирует колонки в
свечи, и внутри каждой берёт high/low по краям окрашенной области, а open/close —
по **ширине** строк: тело свечи широкое, тень узкая. На эталонном графике
(40 свечей, цена пикселя 0,30) ошибка по всем четырём ценам не превысила
0,36 — то есть примерно один пиксель, направление угадано у 40 свечей из 40.

Что этот путь **не умеет**: читать линейные и барные графики (нужны свечи),
отделять наложенные индикаторы от свечей и восстанавливать точное время — оно
считается от таймфрейма и времени последней свечи.

Если авточтение не справилось, ручная разметка никуда не делась: отметить два
опорных уровня с известными ценами, затем swing high, swing low и текущую цену.
В payload тогда попадает `source: "swing-zone-dashboard/screenshot"`.

> **Точность ручного режима.** Шаг разметки равен цене одного пикселя (дашборд
> показывает его в статусе). Нужна точность выше — впишите уровни руками в полях
> Swing High / Swing Low, картинка останется фоном для сверки.

### Дата и окно

Поля **«Дата начала / окончания»** задают рабочее окно: свинги ищутся только внутри
него. Быстрые кнопки — последние 30 / 60 / 120 свечей.

### Метод разметки

| Метод | Как работает | Когда брать |
|---|---|---|
| **KHUSA SM PRO (по умолчанию)** | Вы задаёте две свечи-якоря — SH и SL, дальше движок ведёт структуру сам (схема ниже). Построчный перенос индикатора: дашборд и график считают одно и то же. | Основной режим |
| Автодетект | Свинги ищутся фракталами и зигзагом с фильтром по ATR, без якорей | Быстрый обзор незнакомого инструмента |

### Движок KHUSA SM PRO

```
ручные SH / SL
     ↓  одноразовая коррекция координат старта
INITIAL ENGINE (состояния 0–10)   ← первая пара CSH + CSL по FIB 1
     ↓  последний свинг задаёт направление НАВСЕГДА
MASTER STRUCTURE                  ← bullish либо bearish, подтверждение по FIB 2
     ↓
TSH / TSL                         ← временные экстремумы до подтверждения
     ↓
AUTO SWING ENGINE                 ← необязательный, по умолчанию выключен
```

**Коррекция якорей.** Между двумя указанными свечами движок один раз ищет
максимальный high и минимальный low. Если они выходят за исходные якоря, якоря
заменяются. Обе стороны считаются от оригинальных значений и применяются
одновременно: правка SH не влияет на поиск SL и наоборот. Структурных CSH / CSL
здесь не создаётся — меняются только координаты старта, и от них считается FIB 1.

**INITIAL.** Одиннадцать состояний собирают первую пару CSH + CSL: подход к
FIB 1 сверху запускает нисходящий путь, снизу — восходящий, отдельно
отслеживаются попытки пробоя якорей до касания FIB 1. Пока пара не собрана,
мастер-структура не имеет права стартовать. Как только пара готова, замок
`initialProcessLocked` защёлкивается навсегда: ручные якоря больше не участвуют,
и возврат цены в старую зону ничего не перезапускает.

**MASTER.** Пробой уровня → поиск экстремума → откат до FIB 2 → подтверждение.
Пробой противоположного уровня запоминается, даже если случился до касания
FIB 2, и является обязательным условием подтверждения.

**TSH / TSL** — экстремум, который уже найден, но ещё не подтверждён. Виден в
панели и уходит в payload: агент отличает «уровень есть» от «уровень
подтверждён».

`FIB 1` и `FIB 2` задаются в процентах в панели (по умолчанию 51% и 50%).
Порядок вычислений внутри свечи сохранён таким же, как исполняет Pine: если
состояние сменилось в верхнем блоке, нижний отработает на этой же свече. От
этого зависит результат.

Направление сделки берёт замок структуры, а не `marketTrend`. Пока первая пара
не собрана, дашборд ставит `structure_confirmed: false` и берёт направление по
порядку якорей — об этом прямо написано в статусе, чтобы «short» не выглядел как
решение движка.

> **Сколько раз инициализация доходит до конца.** На 180 прогонах по 4000 свечей
> H1 со случайными данными и автоматическим выбором якорей первая пара собралась
> в 62 случаях (34%). Застревает чаще всего в состояниях 2 и 7 — там, где FIB 1
> пересчитывается от плавающего экстремума и ждёт встречной реакции. Это
> свойство алгоритма, а не сбой: осмысленно выбранные вручную якоря дают лучший
> результат, но рассчитывать на сигнал по любой паре свечей не стоит.

> **Авто-движок выключен по умолчанию** — как и в индикаторе. Если включить, в
> медвежьей ветке состояние 6 переходит в состояние 2, которое выполняется
> только при `autoDirection == 1`, и после первого медвежьего цикла авто-движок
> дальше не идёт. Перенос повторяет это один в один, чтобы дашборд не расходился
> с графиком.

`BULLISH` → покупка на откате в discount, `BEARISH` → продажа в premium. Всё, что
движок сделал от якорей до последней свечи, видно в блоке **«Журнал структуры»**
и уходит в payload полем `structure_events` — это и есть история, по которой
учится агент.

### Как определяются свинги в автодетекте

1. **Фрактал.** Бар считается свинг-хаем, если его `high` выше `high` N соседних
   баров слева и справа (`Сила свинга`). Для свинг-лоу — зеркально.
2. **Зигзаг.** Экстремумы выстраиваются в чередующуюся цепочку high → low → high.
   Два подряд идущих однотипных свинга схлопываются в более экстремальный.
3. **Фильтр импульса.** Движение короче `Мин. импульс × ATR(14)` игнорируется — так
   отсекается рыночный шум. Порог привязан к ATR, поэтому одинаково работает
   и на BTC, и на золоте, и на валютных парах; при отсутствии ATR берётся
   запасной порог 2% от высоты окна.
4. **Площадь работы** — последняя нога структуры: два последних чередующихся свинга.
   Направление ноги задаёт `bias`: нога вверх → ждём откат в discount (long),
   нога вниз → ждём откат в premium (short).

Границы зоны можно **переопределить вручную** в полях Swing High / Swing Low —
весь план пересчитается от ваших уровней (`source: "manual"` в payload).

### Разбор агента

Кнопка **«Разобрать ситуацию»** отправляет разметку на `POST /analyze` и
показывает ответ агента: вердикт `enter / wait / skip` с уверенностью, чтение
структуры, ключевые уровни, рекомендации, риски и условие инвалидации.

Галочка **«Отправлять агенту картинку графика»** прикладывает к запросу PNG
холста — тот же график с уровнями, который видите вы. С картинкой агент
дополнительно заполняет блок **«Что видно на графике»**: свечные формации, гэпы и
уровни, которых нет в цифрах. В режиме скриншота на холст попадает и сам
загруженный снимок — агент смотрит на исходный график, а не только на разметку.

Разбор ничего не исполняет: это аналитика для человека. Автоматически торгует
только `POST /signal`.

### Уровни

| Уровень | Формула (нога вверх, `R = high − low`) |
|---|---|
| equilibrium | `low + R/2` |
| premium / discount | выше / ниже equilibrium |
| OTE | `0.618`–`0.79` отката от экстремума |
| entry | уровень выбранного фибо (по умолчанию `0.705`) |
| stop | `low − буфер·R` |
| TP1 / TP2 | `high` / `high + 0.272·R` |
| размер позиции | `депозит · риск% / |entry − stop|` |

## 2. График TradingView в дашборде

В дашборд встроен виджет Advanced Chart — живой график для визуальной сверки
разметки. Символ по умолчанию `OANDA:XAUUSD`, таймфрейм H4.

> **Чего виджет не умеет.** Загрузить в него наш Pine-индикатор нельзя: встраиваемый
> виджет поддерживает только встроенные индикаторы, приватные скрипты в нём
> недоступны. И данные наружу он не отдаёт — это кросс-доменный iframe. Поэтому
> `expH4` ставится отдельно в самом TradingView, а дашборд считает структуру
> собственным движком по тем же правилам.

## 3. TradingView

Для индикатора **KHUSA SM PRO** возьмите `tradingview/khusa_webhook.pine` и
вставьте его **в конец своего скрипта**, ниже строки
`END AUTOMATIC CONFIRM → MASTER BRIDGE`. Блок ничего не считает заново: берёт
готовые `currentSH / currentSL / vitalityStructureDirection` и шлёт их боту в том же
формате `swing-zone/v1`. Сигнал уходит только когда движок реально передвинул
уровень, а не на каждом баре.

Для автодетектного индикатора:

1. Открыть Pine Editor → вставить `tradingview/swing_zone.pine` → **Add to chart**.
2. Переключить график на **H4** (индикатор предупредит на другом ТФ).
3. Alert → Condition: **Swing Zone H4** → **Any alert() function call** →
   Webhook URL: `https://<ваш-бот>/signal?token=<секрет>`.

Алерт срабатывает на закрытии бара при изменении структуры и отправляет тот же
JSON `swing-zone/v1`. TradingView не умеет отправлять кастомные заголовки —
поэтому секрет передаётся в query-строке (бот принимает оба варианта).

## 4. MetaTrader 5

1. Скопировать `mt5/SwingZone.mq5` в `MQL5/Experts`, скомпилировать (F7).
2. **Сервис → Настройки → Советники → Разрешить WebRequest для следующих URL** —
   добавить адрес бота (без этого `WebRequest` вернёт `-1`).
3. Прикрепить советник к графику, задать `InpBotUrl` и `InpAuthToken`.

Советник считает структуру по `InpTimeframe` (по умолчанию H4) независимо от
таймфрейма графика, рисует уровни объектами `SZ_*`, шлёт сигнал при смене зоны и
пишет план в журнал «Эксперты». Флаг `InpExportCsv` выгружает свечи в
`MQL5/Files/swingzone_h4.csv` — файл можно сразу вставить в дашборд.

### Автоторговля

Замкнутый контур: советник шлёт структуру боту, бот прогоняет её через риск-лимиты
и ИИ-агента, советник забирает решение и исполняет его.

```
MT5 EA  --POST /signal-->  бот (правила + агент)
MT5 EA  --GET  /decision--> {"decision":"enter","side":"buy","entry":...}
MT5 EA  ставит лимитный ордер с SL / TP
```

Включается флагом `InpAutoTrade`. Параметры: `InpMagic`, `InpSlippage`,
`InpMaxLots`, `InpPollSeconds`, `InpExpiryHours`.

Что советник делает сам, не доверяя серверу:

- **Считает объём.** Бот отдаёт `position_size` в абстрактных единицах
  (риск / расстояние до стопа). В MT5 нужен лот с учётом `SYMBOL_TRADE_TICK_VALUE`
  и шага объёма, поэтому советник считает лот заново и обрезает по `InpMaxLots`.
- **Проверяет сторону стопа** — для buy стоп ниже входа, для sell выше.
- **Не дублирует позиции**: если по символу с этим `InpMagic` уже есть позиция или
  ордер, сигнал пропускается.
- **Не исполняет один сигнал дважды** — сверяется по `signal_id`.
- **Игнорирует протухшие решения** — бот помечает их `decision: "stale"` после
  `DECISION_TTL_MINUTES` (по умолчанию 4 часа).

Ордер выставляется лимитный, со сроком жизни `InpExpiryHours` — если цена не
пришла в зону входа, он снимается сам.

## 6. Бот и ИИ-агент

```bash
pip install -r requirements.txt
cp bot/.env.example .env      # заполнить BOT_AUTH_TOKEN и лимиты
uvicorn bot.app:app --host 0.0.0.0 --port 8000
```

Маршруты сервиса:

| Маршрут | Назначение |
|---|---|
| `GET /` | дашборд (статика из `web/`) |
| `POST /signal` | приём сигнала от дашборда, TradingView или MT5 |
| `POST /analyze` | разбор ситуации агентом: цифры + скриншот графика, без исполнения |
| `POST /vision` | распознавание ценовой шкалы скриншота для авто-калибровки |
| `GET /decision?symbol=` | последнее решение для исполнителя (советник MT5) |
| `GET /health` | healthcheck для Railway |
| `GET /docs` | автодокументация OpenAPI |

Порядок обработки `POST /signal`:

1. **Проверка токена** — заголовок `X-Auth-Token` или query-параметр `token`.
2. **Жёсткие правила** (`run_guards`) — их ИИ обойти не может: белый список
   инструментов, `risk_pct ≤ MAX_RISK_PCT`, `R:R ≥ MIN_RR`, стоп по правильную
   сторону от входа, `side` совпадает с `bias`, вход внутри зоны, возраст данных
   ≤ `MAX_DATA_AGE_HOURS`.
3. **ИИ-агент** (`agent.decide`) — Claude получает весь контекст структуры и
   возвращает строго типизированный ответ (structured outputs):

```json
{
  "decision": "enter",
  "confidence": 0.72,
  "side": "buy",
  "entry": 115000.0,
  "stop_loss": 111842.5,
  "take_profit": [121450.0, 123938.8],
  "position_size": 0.03167,
  "trigger": null,
  "reasons": ["цена в зоне OTE", "R:R 2.04 выше порога"],
  "risks": ["ATR 10.7% от зоны — возможен прострел стопа"]
}
```

Модель по умолчанию — `claude-opus-5` с адаптивным мышлением. Если
`ANTHROPIC_API_KEY` не задан или вызов упал, бот переходит на детерминированный
фолбэк на правилах: сервис не падает и не «зависает» на сигнале.

4. **Исполнение** — `DRY_RUN=true` (по умолчанию) только логирует ордер. Для
   реальной торговли подключите SDK биржи в `execute()` в `bot/app.py`.

Все сигналы и решения пишутся в `signals.jsonl` — готовый журнал для разбора.

Валидируется обязательный минимум схемы, но лишние поля не выбрасываются:
`structure_events`, `window` и `agent` доходят до модели целиком — именно они дают
ей контекст, которого нет в цифрах плана.

### `POST /analyze` — разбор с картинкой

Тот же сигнал плюс необязательное поле `image` с data-URL картинки:

```json
{ "signal": { "schema": "swing-zone/v1", "...": "..." },
  "image": "data:image/png;base64,iVBORw0KG..." }
```

Ответ — структурированный разбор (`AgentAnalysis`): `verdict`, `confidence`,
`summary`, `structure_read`, `key_levels`, `recommendations`, `risks`,
`invalidation`, `chart_notes`.

Картинка проверяется до обращения к модели: допускаются `png`, `jpeg`, `webp`,
`gif`, размер — не больше `MAX_IMAGE_MB` (по умолчанию 5 МБ), иначе `413`.
Жёсткие риск-лимиты здесь не применяются: разбор ничего не исполняет, он должен
уметь честно сказать «этот сетап брать нельзя, вот почему». Без
`ANTHROPIC_API_KEY` возвращается фолбэк, собранный по цифрам payload, с пустым
`chart_notes` — картинку в этом режиме никто не читал.

### CORS

Дашборд раздаётся тем же сервисом, поэтому его запросы идут на свой origin и CORS
не нужен. Настройка `ALLOWED_ORIGINS` пригодится, только если вы открываете
дашборд с другого домена (например, локальную копию против прод-бота). TradingView
и MT5 шлют серверные запросы — им CORS не требуется в любом случае.

## 7. Деплой на Railway

Один сервис поднимает и дашборд, и API.

1. **New Project → Deploy from GitHub repo** → выбрать `swing-zone`.
   Репозиторий приватный — при первом деплое Railway попросит выдать доступ
   к нему в настройках GitHub-приложения.
2. Railway читает `railway.toml` и `Procfile`, ставит зависимости из
   `requirements.txt` и запускает
   `uvicorn bot.app:app --host 0.0.0.0 --port $PORT`. Порт подставляется
   платформой — не задавайте его вручную.
3. **Variables** — задать переменные окружения (полный список в `bot/.env.example`):

   | Переменная | Зачем |
   |---|---|
   | `BOT_AUTH_TOKEN` | секрет для `/signal`; без него эндпоинт открыт всем |
   | `ANTHROPIC_API_KEY` | ключ ИИ-агента; без него работает фолбэк на правилах |
   | `MIN_RR`, `MAX_RISK_PCT`, `MAX_DATA_AGE_HOURS` | жёсткие риск-лимиты |
   | `ALLOWED_SYMBOLS` | белый список инструментов |
   | `MAX_IMAGE_MB` | потолок размера скриншота для `/analyze` |
   | `DRY_RUN` | `true` — ордера только логируются |

4. **Settings → Networking → Generate Domain** — получить публичный адрес.
   Дашборд откроется на нём же, поле вебхука подставится автоматически.
5. Прописать этот адрес в TradingView (`https://<домен>/signal?token=<секрет>`)
   и в MT5 (`InpBotUrl` + разрешить URL в настройках терминала).

Healthcheck настроен на `/health` — Railway перезапустит сервис, если он перестанет
отвечать. Логи решений видны в **Deployments → Logs**.

Проверить, что агент действительно живой, а не сидит на фолбэке:
`curl https://<домен>/health` → поле `agent` должно быть `"claude"`, а не
`"rules"`. Пошаговая инструкция со всеми переменными, вариантом деплоя
через `railway up` без GitHub и разбором типовых ошибок — в
[`DEPLOY.md`](DEPLOY.md).

> **Журнал сделок.** `signals.jsonl` пишется в файловую систему контейнера, которая
> при передеплое обнуляется. Если журнал нужен надолго — подключите Railway Volume
> и укажите `JOURNAL_PATH=/data/signals.jsonl` либо пишите в внешнюю БД.

> **Приватность демо.** Публичный домен Railway открыт всем, у кого есть ссылка,
> — дашборд не требует входа. Сам по себе он безвреден (считает в браузере), но
> `/signal` обязательно закройте `BOT_AUTH_TOKEN`.

## Ограничения

- Дашборд — инструмент разметки и расчёта, а **не торговый сигнал**.
- Свинги подтверждаются с задержкой в `N` баров (свойство фрактала): последний
  экстремум становится известен только через N закрытых свечей.
- Размер позиции считается линейно (`риск / расстояние до стопа`) — для фьючерсов
  и форекса пересчитайте под контракт и стоимость пункта на стороне бота.
- Перед реальной торговлей прогоните связку на демо-счёте и держите `DRY_RUN=true`.
