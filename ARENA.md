# Swing Zone Arena — турнирная площадка

Сайт с регистрацией, профилями, бумажной торговлей на общих котировках,
таблицей результатов и подсказками.

Автор: Vitaliy Yugay · vamp.09.94@gmail.com · https://github.com/YugayV

## Что где живёт

| Путь | Что это |
|---|---|
| `arena/db.py` | Схема и подключение. Один DDL работает и на SQLite, и на Postgres |
| `arena/auth.py` | Регистрация, вход, сессии. Пароли — Argon2id |
| `arena/quotes.py` | Хранилище котировок, свёртки старших таймфреймов |
| `arena/engine.py` | Бумажная торговля: исполнение ордеров, стопы, цели, счёт |
| `arena/tournament.py` | Турниры и участники |
| `arena/hints.py` | Подсказки: правила бесплатно, модель по квоте |
| `arena/api.py` | HTTP-интерфейс `/api/*` |

Адреса на сайте: `/` — площадка, `/dashboard/` — прежний дашборд разметки.
Обе части в одном сервисе.

## Три правила, ради которых всё написано

Бумажная торговля ценна не реализмом, а невозможностью выиграть за счёт
информации, которой нет у остальных. Отсюда три правила в `arena/engine.py`:

**1. Отложенный ордер исполняется только свечами строго позже размещения.**
Иначе участник видит хай уже сформированной свечи и ставит лимитку, которая
«сработала» в прошлом. Проверяется условием `placed_ms < candle.ts`.

**2. Отставший поток закрывает торговлю для всех.**
Рядом на странице живёт виджет TradingView с настоящей ценой. Если наш ряд
свечей отстаёт, участник видит будущее относительно нашей базы и может
входить по устаревшей цене без риска. При отставании больше `MAX_FEED_LAG_S`
(по умолчанию 180 с) приём ордеров прекращается — и это видно в шапке сайта.

**3. Если внутри свечи достижимы и стоп, и цель — засчитывается стоп.**
Порядок тиков внутри свечи неизвестен, и трактовать неизвестность в пользу
участника значит завышать результаты у всех сразу.

Дополнительно: стоп обязателен, объём считается из процента риска (а не
задаётся на глаз), спред вычитается на входе и на выходе, действуют пределы
на число открытых сделок и висящих ордеров.

## Откуда берутся котировки

Виджет TradingView на сайте — **только картинка**. Данных из него на сервере
нет, и зачёт по нему не считается. Свой ряд свечей наполняется одним из
способов:

### Мост из MT5 (бесплатно, рекомендуется)

`mt5/ArenaFeed.mq5` шлёт закрытые минутные свечи вашего брокера на
`POST /api/quotes/ingest`. Это ровно тот фид, на котором вы торгуете.

1. Сервис → Настройки → Советники → разрешить WebRequest для адреса площадки.
2. Прикрепить советник к графику нужного символа.
3. Заполнить `InpArenaUrl` и `InpIngestToken` (тот же, что `QUOTES_INGEST_TOKEN`).

Советник отправляет только **закрытые** свечи: незакрытая меняется на каждом
тике, и по ней участники увидели бы будущее текущей минуты.

Минус способа честный: пока терминал выключен, поток стоит — и торговля
автоматически закрывается по правилу №2.

### Заливка истории из файла

```bash
node tools/csv2json.mjs data/XAUUSD_M1.csv > candles.json
python3 tools/arena_admin.py load candles.json --symbol XAUUSD --tf M1
```

Разбор идёт общим модулем `web/csv.js` — тем же, что у дашборда и бэктестера,
поэтому выгрузка investing.com читается правильно (у неё close стоит вторым).

### Любой свой источник

`POST /api/quotes/ingest` с заголовком `X-Ingest-Token` принимает
`{"symbol","tf","candles":[{"ts","o","h","l","c","v"}]}`, где `ts` — миллисекунды
UTC. Скрипт на чём угодно подойдёт.

### Демо-данные

```bash
python3 tools/arena_admin.py demo --bars 20000 --tf M1
```

Случайное блуждание для проверки сайта до подключения настоящего потока.
Это **не рынок** — команда честно об этом печатает.

## Свёртки таймфреймов

Хранится базовый таймфрейм (M1), а M15/H1/H4/D1 материализуются при каждом
приёме котировок — пересобираются только задетые корзины.

Собирать их на лету нельзя: 300 дневных свечей — это 432 000 минутных строк
на один запрос графика. 20 000 минуток сворачиваются примерно за 0.7 с.

## Подсказки

**Разбор по правилам** — бесплатно, всегда, без модели. Считает площадь
работы, где сейчас цена (премиум / дискаунт / равновесие), уровни OTE,
R:R задуманной сделки и предупреждения: покупка в премиуме, стоп шире
половины площади, слишком тесный стоп.

**Подсказка модели** — по кнопке и с квотой (`AI_QUOTA_PER_DAY`, по умолчанию
10 в сутки на участника). Провайдер выбирается переменной `AI_PROVIDER`:

| Значение | Что делает |
|---|---|
| `off` | модель отключена, работают только правила (по умолчанию) |
| `deepseek` | `DEEPSEEK_API_KEY`, OpenAI-совместимый вызов, самый дешёвый вариант |
| `anthropic` | `ANTHROPIC_API_KEY`, по умолчанию Haiku — дороже, но качественнее |

Квота списывается **до** вызова, а не после: иначе шквал ошибок провайдера
позволил бы обойти лимит. Если модель недоступна, участник всё равно получает
разбор по правилам — сайт не ломается из-за внешнего сервиса.

Ответ модели жёстко ограничен схемой: свободный текст в торговый интерфейс
не попадает.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATABASE_URL` | `sqlite:///arena.db` | На Railway подставляется плагином Postgres |
| `QUOTES_INGEST_TOKEN` | — | **Обязателен.** Без него приём котировок отключён |
| `ARENA_BASE_TF` | `M1` | Базовый таймфрейм хранения |
| `MAX_FEED_LAG_S` | `180` | Отставание потока, после которого торговля закрывается |
| `MAX_OPEN_TRADES` | `5` | Предел одновременно открытых сделок |
| `MAX_PENDING_ORDERS` | `10` | Предел висящих отложенных ордеров |
| `AI_PROVIDER` | `off` | `off` / `deepseek` / `anthropic` |
| `DEEPSEEK_API_KEY` | — | Ключ, если выбран deepseek |
| `AI_QUOTA_PER_DAY` | `10` | Подсказок модели на участника в сутки |
| `SECURE_COOKIES` | `auto` | На Railway куки автоматически становятся Secure |
| `ARENA_ENABLED` | `true` | `false` — площадка выключена, остаётся дашборд |

## Запуск локально

```bash
pip install -r requirements.txt

export DATABASE_URL="sqlite:///arena.db"
export QUOTES_INGEST_TOKEN="devtoken"

python3 tools/arena_admin.py tournament "Тест" XAUUSD --tf M1 --days 30
python3 tools/arena_admin.py demo --bars 20000

uvicorn bot.app:app --port 8000
```

Сайт откроется на `http://127.0.0.1:8000/`.

Тесты движка:

```bash
python3 tools/test_arena.py
```

## Деплой на Railway

К инструкции из `DEPLOY.md` добавляется база:

1. В проекте: **New → Database → Add PostgreSQL**. Railway сам подставит
   `DATABASE_URL` в сервис.
2. Добавить `QUOTES_INGEST_TOKEN` (длинная случайная строка) и, если нужна
   модель, `AI_PROVIDER=deepseek` + `DEEPSEEK_API_KEY`.
3. После деплоя создать турнир:
   ```bash
   railway run python3 tools/arena_admin.py tournament "Сентябрь" XAUUSD --days 30
   ```
4. Запустить `mt5/ArenaFeed.mq5` в терминале — поток пойдёт на площадку.

Схема базы создаётся сама при старте сервиса: отдельный шаг миграции не нужен.
В отличие от журнала сигналов, данные площадки в Postgres переживают редеплой.

## Чего в этой версии нет

Честный список, чтобы не было сюрпризов:

- **Подтверждения почты и восстановления пароля.** Забытый пароль сейчас
  чинится только через базу. Нужен внешний почтовый сервис.
- **Защиты от нескольких аккаунтов одного человека.** Для учебного турнира
  среди своих это терпимо, для публичного — нет.
- **Ограничения частоты запросов.** Регистрацию и вход стоит закрыть
  rate-limit'ом до публичного запуска.
- **Кредитного плеча и маржи.** Объём считается от риска, маржинальные
  требования не моделируются: счёт не может получить margin call.
- **Комиссии и свопов.** Учитывается только спред.
- **Проверки вызова DeepSeek на живом ключе.** Код написан по их
  OpenAI-совместимому интерфейсу, но без ключа проверить было нечем.
