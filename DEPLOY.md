# Деплой на Railway

Один сервис Railway отдаёт всё сразу:

| Адрес | Что там |
|---|---|
| `/` | турнирная площадка: регистрация, торговля, таблица |
| `/dashboard/` | дашборд разметки H4 |
| `/api/*` | API площадки |
| `/signal`, `/analyze`, `/vision`, `/decision` | торговый бот |
| `/health`, `/api/health` | проверки живости |

Отдельный фронтенд-хостинг не нужен.

Автор: Vitaliy Yugay · vamp.09.94@gmail.com · https://github.com/YugayV

## 1. Залить код

### Вариант А — через GitHub (рекомендуется)

Код уже лежит в **https://github.com/YugayV/arena**, ветка `main`.

В Railway: **New Project → Deploy from GitHub repo → arena**. Репозиторий
приватный — при первом деплое Railway попросит выдать доступ в настройках
GitHub-приложения.

Плюс варианта: каждый `git push` пересобирает сервис, а GitHub Actions
прогоняет тесты до этого (файл `.github/workflows/checks.yml`).

### Вариант Б — без GitHub, прямо с машины

```bash
npm i -g @railway/cli
railway login
railway init          # создаёт проект
railway up            # заливает текущий каталог и собирает
```

Работает сразу, но автодеплоя по push не будет.

## 1.5. База для турнирной площадки

Если разворачивается сайт турнира (`ARENA.md`), в проекте нужна база:
**New → Database → Add PostgreSQL**. Railway сам подставит `DATABASE_URL` в
сервис — руками её задавать не нужно.

Схема создаётся при старте сервиса, отдельного шага миграции нет. Данные
площадки живут в Postgres и переживают редеплой, в отличие от файлового
журнала сигналов.

Без базы площадка просто не поднимется, а бот и дашборд продолжат работать:
на `/` тогда отдаётся дашборд.

## 2. Переменные окружения

Railway → сервис → **Variables**. Это единственный шаг, от которого
зависит, будет агент живым или нет.

### Обязательные

| Переменная | Значение | Что даёт |
|---|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` | **Именно она включает агента.** Без неё `/analyze` и `/decision` молча уходят на фолбэк по правилам, а `/vision` вообще не читает скриншот |
| `BOT_AUTH_TOKEN` | длинная случайная строка | секрет для `/signal`, `/analyze`, `/vision`. Без него ручки открыты всему интернету |
| `QUOTES_INGEST_TOKEN` | длинная случайная строка | нужен площадке: без него приём котировок отключён и турнир не получит данных |

Токен сгенерировать так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

### Для турнирной площадки

| Переменная | Пример | Смысл |
|---|---|---|
| `ARENA_DEFAULT_TOURNAMENT` | `Открытый турнир` | Турнир создастся сам при первом старте. Без неё свежий деплой открывается страницей «активного турнира нет» |
| `ARENA_DEFAULT_SYMBOLS` | `XAUUSD,EURUSD,GBPUSD,USDJPY,BTCUSD,US500` | Инструменты турнира |
| `ARENA_DEFAULT_DAYS` | `30` | Длительность |
| `ARENA_DEFAULT_BALANCE` | `10000` | Стартовый депозит |
| `MAX_FEED_LAG_S` | `180` | Отставание потока, после которого торговля закрывается всем |
| `FEED_PROVIDER` + `FEED_API_KEY` | `twelvedata` | Загрузчик котировок, если нет моста из MT5 |
| `AI_PROVIDER` + ключ | `deepseek` | Подсказки модели; без них работают только правила |

Турнир создаётся **один раз**: если в базе уже есть незакончившийся,
перезапуск сервиса ничего не тронет и счета участников не сбросит.

### Стоит выставить сразу

| Переменная | Рекомендую | Смысл |
|---|---|---|
| `DRY_RUN` | `true` | сигналы пишутся в журнал, но исполнение не разрешается. Снимать только после недели наблюдения |
| `ALLOWED_SYMBOLS` | `XAUUSD` | бот не примет сигнал по чужому инструменту |
| `MAX_RISK_PCT` | `1.0` | потолок риска на сделку |
| `MAX_DATA_AGE_HOURS` | `8` | старше — сигнал протух |
| `ANTHROPIC_MODEL` | `claude-opus-5` | значение по умолчанию, менять не обязательно |
| `ANTHROPIC_EFFORT` | `high` | глубина разбора для `/analyze` и `/decision` |
| `ANTHROPIC_VISION_EFFORT` | `medium` | чтение скриншота — задача проще, платить за `high` незачем |
| `MAX_IMAGE_MB` | `5` | потолок размера скриншота |
| `ALLOWED_ORIGINS` | ваш домен | CORS. `*` оставлять только на время отладки |

`MIN_RR` трогать не надо: R:R в этой схеме — структурная константа 2.0435
(вход 0.705, стоп 0.345), так что порог 2.0 не отсечёт ни один сигнал
дашборда. Он ловит только сигналы с чужой геометрией.

### Про журнал

Файловая система Railway **эфемерная**: `signals.jsonl` и последнее решение
для MT5 стираются при каждом редеплое. Если журнал нужен надолго —
подключите Volume:

Railway → сервис → **Volumes → New Volume**, mount path `/data`, затем

```
JOURNAL_PATH=/data/signals.jsonl
```

`/health` вернёт `"journal_persistent": true` — по этому полю видно, что
том подхватился.

## 3.5. Проверка после деплоя

В проекте есть скрипт, который делает то же, что сделал бы первый участник:
регистрируется, входит в турнир, ставит сделку, просит разбор, смотрит
таблицу. Ответ «сервис отвечает 200» ничего не значит, если при этом нельзя
торговать.

```bash
python3 tools/smoke.py https://<домен> --ingest-token <QUOTES_INGEST_TOKEN>
```

Пример здорового прогона:

```
--- турнир ---
  ok   турнир существует: Открытый турнир
  ok   инструменты назначены: BTCUSD, EURUSD, USDJPY, XAUUSD
       XAUUSD   11 с назад
  ok   есть хотя бы один свежий инструмент
--- участник ---
  ok   регистрация
  ok   разбор по правилам: уровней 5
  ok   сделка принята
  ok   сделка без стопа отклонена: HTTP 400
  ok   превышение риска отклонено: HTTP 400
--- защита ---
  ok   торговля без входа закрыта: HTTP 401

итого: 33 успешно, 0 провалов
```

Скрипт заводит настоящий тестовый аккаунт со случайной почтой — на боевой
площадке он останется в базе и в таблице. Это разовая проверка после
деплоя, а не то, что гоняют по расписанию. Флаг `--read-only` проверяет
только то, что не меняет данные.

Приём котировок проверяется **пустой пачкой**: вписывать выдуманную цену в
боевой ряд нельзя — по нему считается зачёт, и одна фальшивая свеча может
сорвать чужой стоп.

Код возврата 0 — всё хорошо, 1 — есть провалы, так что скрипт годится и для
автоматики.

## 4. Проверить, что агент действительно живой

```bash
curl https://<домен>/health
```

Ожидаемый ответ:

```json
{
  "status": "ok",
  "dry_run": true,
  "min_rr": 2.0,
  "max_risk_pct": 1.0,
  "agent": "claude",
  "model": "claude-opus-5",
  "journal": "/data/signals.jsonl",
  "journal_persistent": true
}
```

**`"agent": "claude"` — это и есть ответ на вопрос «агент рабочий?».**
Если там `"rules"`, ключ не подхватился: проверьте имя переменной и то, что
после её добавления сервис пересобрался.

Ключ наружу не отдаётся — только факт, что он задан.

Второй, более честный тест — реальный вызов модели:

```bash
curl -X POST https://<домен>/analyze \
  -H "X-Auth-Token: <ваш BOT_AUTH_TOKEN>" \
  -H "Content-Type: application/json" \
  --data-binary @sample_signal.json
```

Если в ответе среди `risks` есть строка
`«разбор без ИИ-агента: ключ API не задан»` — работает фолбэк, а не модель.
У живого агента этой строки нет, а `structure_read` и `chart_notes`
содержат осмысленный текст, а не шаблон.

Открыть дашборд: `https://<домен>/` — он отдаётся тем же сервисом.

## 5. Подключить источники

**TradingView.** В своём скрипте VitalityTr SM PRO включите блок
`tradingview/vitalitytr_webhook.pine`, затем Alert → Any alert() function call →
Webhook URL:

```
https://<домен>/signal?token=<BOT_AUTH_TOKEN>
```

Секрет идёт в query-строке, потому что TradingView не умеет слать
кастомные заголовки. Бот принимает оба варианта.

**MT5.** В советнике `mt5/` выставьте `InpBotUrl = https://<домен>` и
добавьте домен в *Сервис → Настройки → Советники → Разрешить WebRequest*.

**Дашборд.** В поле адреса бота на странице укажите тот же домен и токен.

## 6. Что может пойти не так

| Симптом | Причина | Что делать |
|---|---|---|
| Healthcheck красный при старте | сервис не поднялся | Deploy Logs: обычно опечатка в `railway.toml` или отсутствующая зависимость |
| `/health` отвечает, `"agent": "rules"` | `ANTHROPIC_API_KEY` не задан или задан в другом сервисе проекта | добавить в Variables **этого** сервиса и дождаться редеплоя |
| `/analyze` возвращает 401 | не передан `X-Auth-Token` | заголовок или `?token=` |
| `/analyze` возвращает 500 после ключа | старый SDK — `messages.parse` не существует | `requirements.txt` должен требовать `anthropic>=0.121`; пересобрать без кеша |
| Ответ агента пустой, в логах `refusal` | модель отклонила запрос своими классификаторами | штатно обрабатывается: код проверяет `stop_reason == "refusal"` и уходит на фолбэк. Если такое повторяется часто — стоит включить серверный fallback (бета-заголовок `server-side-fallback-2026-07-01`) |
| Журнал пуст после редеплоя | эфемерный диск | подключить Volume и задать `JOURNAL_PATH=/data/...` |
| `/vision` отвечает «авточтение недоступно» | нет ключа | та же `ANTHROPIC_API_KEY` |

## 7. Сколько это стоит

Railway: базовый тариф ~$5/мес, сервис такого размера в него укладывается.

Anthropic: платится отдельно по факту вызовов. `/analyze` — это один
запрос на разметку, не на каждую свечу; при частоте порядка одного
сигнала на 300 баров расходы на модель заметно меньше расходов на хостинг.
Основной расход даёт `/vision`, если читать скриншоты часто — поэтому
`ANTHROPIC_VISION_EFFORT` и стоит держать на `medium`.
